# 弈仙牌助手：已验证数值规则云源

公告完整性监测组件（开发中，未发布）：不再把“78 个已注册数值牌面”或旧 `accepted_notices` 当作整份公告的仙命覆盖证明。监测器逐层读取完整平衡调整段，记录所有条目；批量仙命名单逐个登记。每个未审条目进入 `pending`，已接受的旧公告也重新检查，不能因已登记其中一张牌就跳过其他仙命。活动牌仅在有精确审查记录时排除。

`monitor_state` 仅代表资料源检查是否正常。客户端还须读取 `coverage_state` 和 `announcement_coverage`：后者包含 `scope=all_balance_items`、最新公告 ID、逐项摘要与待审数、各公告的来源/完整平衡段 SHA、每项 ID/SHA。`supported_faces_scope` 和 `accepted_notices_scope` 均为 `registered_numeric_faces_only`。`reviewed` 表示相应范围有审查收据，仍须匹配条目声明的客户端版本与引擎合同；不宣称本机已经具备全部机制。抓取失败保留既有待审项并标为 `source_unavailable`，短新闻列表中消失的公告也不自动清除待审项。

机制审查使用本仓库本地静态文件 `notice_coverage_reviews.json`（可选，缺失时保持待审），不从公告下载或执行代码。格式为 `schema=1`、`notices[公告gid]`，每份记录须提供精确 `source`、`balance_sha256`、`items[条目item_id]`。每项必须且只能含 `item_sha256`、`kind`（`mechanism` 或 `activity_excluded`）、`engine_contract`、`minimum_assistant_version`（三段数字版本）、非空 `evidence_sha256` 列表。来源、完整调整段、条目、合同或证据不符时拒绝复用。填入记录前需独立审查实现与测试；这个文件本身不能为未实现机制增加支持。

自动数值更新同时限定为已知属性的完整句式：附加新机制、重复牌名、未知属性、变更攻击次数或未经审查的原生牌面均待审。原身份、等级、费用、模板、数值范围和完整包校验仍保留。该组件没有更改规则包、registry 或客户端合同；正式数值/仙命数据由整合任务另行验收发布。

2026-10-22：云规则 `2026.10.22.6` 同步狂剑·赤霄三个等级的加攻上限 1/2/3 和基础攻击 6。公告监测分别绑定上限与基础攻击的参数位置，避免把上限调整误读为攻击调整。基础攻击由已安装 build 26125017 的 CardConfig 与当前 Wiki 交叉核验，公告只作为上限变化的依据。其余 75 个注册牌面逐字段不变，旧规则包保持不可变。全部 37 项云仓测试、实际未修改的 1.1.356 引擎 30 个新旧规则战斗场景和客户端升级/固定快照/坏包拒绝/幂等验证通过，见 `audits/2026-10-22-*`。无需升级助手程序；后台下载后下局固定使用。

本仓库的公告接受记录与“无待适配项”仅覆盖已注册数值牌包，不表示整份公告中的主动/被动仙命、新增机制或其他牌型全部完成模拟适配；活动卡牌不纳入本次更新。

本仓库存放公开牌效资料、受控数值模板和公告监测脚本。助手游戏操作源码、账号信息与实战日志不在本仓库。

初始规则基于 2026 年 10 月 8 日官方公告。首批注册 54 个准确原生牌面：该公告的 45 个牌面及 9 个已经核验的普通固定攻击牌面。相同原生 ID、等级和已支持效果模板中的数字变化可生成数据更新；新增效果、未注册模板、含糊公告和未核验费用变化会标记待适配。

GitHub Actions 每 5 分钟检查官方 Steam 公告和注册的 Wiki 页面。平台调度可能延迟。只有完整数据候选通过协议校验才会更新 `public/manifest.json`，否则保留上次已验证规则，并写入 `public/monitor_status.json`。

助手从 HTTPS 云源读取清单、校验模板与内容哈希，在后台准备更新，并在下一局固定一份不可变规则快照。已开始的对局不会混用规则。接收端最低版本为 1.1.283；1.1.282 尚不具备完整的云数值接收功能。

公开规则入口：`public/manifest.json`。当前工作流只发布数据，不执行公告中的文字或下载外部代码。

复杂仙命机制、未注册卡牌与游戏客户端修复仍需要对应引擎版本核验。监测到公告不等于该公告全部已适配。
